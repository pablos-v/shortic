# Готовый некоммерческий сервис сокращения ссылкок на Java.

## Как работает сервис. Описание.
Сервис позволяет создавать короткие ссылки и отслеживать статистику кликов по ним.

Архитектура постороена на микросервисах. В процессе запуска создаются Docker контейнеры:
1. nginx-proxy - прокси для реализации HTTPS перенаправления запросов с портов 80 и 443 на frontend
2. letsencrypt - для автоматического получения и продления сертификатов SSL от LetsEncrypt
3. db-postgres - БД для backend-counting-service, в ней будет вся статистика по кликам
4. fast-postgres - БД для backend-giving-service, отвечает за отдачу полной ссылки
5. redis - для кэширования запросов
6. config-server - сервер конфигурации SPRING Config
7. discovery-service - сервер eureka для обнаружения и регистрации новых инстансов сервисов (полезно для горизонтального роста вссего SaaS)
8. backend-giving-service - сервис быстрой отдачи полных ссылок
9. backend-counting-service - сервис, который хранит сущности ссылок, считает статистику кликов и проверяет ссылки на безопасность
10. frontend - сервис фронтенда (работает на шаблонизаторе ThymeLeaf)

При создании короткой ссылки длинная ссылка проверяется на опасность сервисом Яндекса "Safe browsing" - если ссылка безопасна, то короткая ссылка будет активна.
Если нужно отслеживать статистику кликов по короткой ссылке - следует придумать и указать 5-значный цифровой пароль для короткой ссылки, по нему можно будет управлять ссылкой и смотреть статистику.
Длинную ссылку в дальнейшем можно изменить. При попытках изменения на опасную ссылку - короткая ссылка блокируется, и дальнейшая работа с ней невозможна.
Также, происходит периодическая проверка ссылок на опасность. Периодичность определяется в backendcountingservice.service.ScheduledLinkCheckingService.checkAllLinksByPeriod() константой CRON_PERIOD.

Когда происходит клик по короткой ссылке - из БД или из кэша REDIS достаётся длинная ссылка и происходит редирект.
Параллельно, отдельным потоком происходит отправка статистики клика. 
Данные статистики получаются от браузера пользователя, и обрезаются в методе prepareClickDTO класса GivingService до длинны значений, которые точно поместятся в созданные таблицы (параметры таблиц описываются в backend-counting-service/src/main/resources/db/changelog/v.1.0.0/create-tables.xml).

## Инструкция по развертыванию веб-приложения:

Для развёртывания приложения на вашем сервере, нужны docker и docker compose. Установите их предварительно.
Например, на Ubuntu можно сделать это одной командой: apt install docker.io docker-compose

Далее необходимо скопировать содержимое репозитория командой: git clone https://github.com/pablos-v/shortic

Теперь пора получить ключ АПИ для проверки ссылок. Применяется логика работы с АПИ яндекса: https://yandex.ru/dev/safebrowsing/
Регистрируетесь в каб. разработчика https://developer.tech.yandex.ru/ и нажимаете "получить АПИ ключи" -> Safe browsing API - и вот он ваш ключ. Вставьте его в .env файл.
Документация тут: https://yandex.ru/dev/safebrowsing/doc/ru/

Почти вся конфигурация выполняется в файле .env
Есть шаблон .env_example с комментариями, нужно его заполнить своими параметрами и переименовать в .env
Таблицы создаются в соответствии со значениями настройки создания таблиц из
backend-counting-service/src/main/resources/db/changelog/v.1.0.0/create-tables.xml и
backend-giving-service/src/main/resources/db/changelog/v.1.0.0/create-tables.xml

После конфигурации достаточно перейти в директорию с docker-compose.yaml и запустить команду docker-compose up.
